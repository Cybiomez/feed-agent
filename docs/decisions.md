# Журнал решений — feed-agent

Формат: дата — решение — почему. Сюда же осознанные упрощения и дыры с планом закрытия.

## 24-09-2026 — старт MVP

- **Провайдер модели по умолчанию — QWEN через OpenRouter.** OpenAI-совместимый API →
  абстракция провайдера тривиальна, позже DashScope/локальную/Claude подменяем одной
  строкой конфига. Один ключ, бесплатные qwen-модели, дёшево для потока заголовков.
  - *Упрощение/риск:* у бесплатного тира OpenRouter есть лимиты частоты, модели иногда
    снимают. Смягчение: id модели — в конфиге (`settings.toml`), заголовки оцениваем
    **пачкой** за один запрос, прогон 2–3×/день. План: при упоре в лимит — DashScope или
    вторая модель как fallback.
- **Ключ — вне репозитория.** Читается из `OPENROUTER_API_KEY`; в бою наполняется из
  Vaultwarden через брокер `secret` в EnvironmentFile systemd. В git/config — никогда.
- **Оценка пачкой, полный текст не гоняем.** На модель уходят только заголовок+описание.
  Полный текст сжимаем (выжимка) только у прошедших порог — экономия токенов и приватность.
- **Отбор смещён в полноту (§ТЗ 3).** При сомнении — оставлять. Порог мягкий, настраивается.
- **Дедупликация — по хешу** (url + нормализованный заголовок). Уже виденное не повторяем.
- **Доставка — только через `notify`** (шов L1 не дублируем): дайджест уходит пайпом в
  `~/.local/bin/notify`, формат HTML.
- **Хранилище — SQLite** (`data/feed.db`): таблицы `sources`, `items`, `scores`, `reactions`,
  `kv` (профиль-мета/состояние). Открытые форматы, переносимо (§25).
- **Заглушка-провайдер** (`providers/stub.py`) — эвристика по стоп-словам/интересам из
  профиля, чтобы гонять пайплайн без ключа/сети (сухой прогон и тесты). Не решение по
  качеству — только чтобы механизм ехал.

## 24-09-2026 — холодный старт: сначала льём всё, учимся на реакциях

- **Решение Алексея:** пока вкус не выучен — **не фильтровать**, отдавать весь поток
  (дедуплицированный), а таргетную фильтрацию включить позже, когда накопятся реакции
  👍/👎. Это правильный cold-start: не терять нужное, пока сигнала о вкусе нет.
- **Как выражено в коде:** `threshold = 0` (проходит всё), `provider = "stub"` (модель для
  фильтра не нужна → ключ OpenRouter пока не требуется). OpenRouter/QWEN подключим на этапе
  фильтрации. `digest_max_items = 25` — предел на одно сообщение Telegram.
- **Следствие для этапа 2 (реакции):** «учиться на реакциях» требует интерактивных
  сообщений с кнопками 👍/👎 и обработки нажатий (callback_query). Шов `notify` умеет только
  ОТПРАВЛЯТЬ текст — приём нажатий это отдельная способность. Решить на этапе 2: расширить
  бот `eco-notify` или дать фид-агенту свой узкий бот-приёмник реакций. Пока — просто поток.

## 24-09-2026 — доставка в свою тему и развёртывание

- **Доставка — в отдельную тему «Новости»**, не в тред алертов. Шов `notify` расширен
  разовым адресом `--to CHAT [THREAD]` (дефолтный target не меняется); тема — в
  `settings.toml` (`target_chat=-1003930969610`, `target_thread=138`). Правка notify — в eco.
- **Развёрнут:** пользовательский systemd-таймер `feed-agent.timer`, 3×/день
  (09/14/20 UTC = 12/17/23 МСК; бокс в UTC), linger включён — идёт без входа. Сервис несёт
  свой PATH (чтобы нашёлся notify), EnvironmentFile необязателен (заглушка без ключа).
  Манифест зарегистрирован в реестре Console (`~/.config/eco/registry/08-feed-agent.json`).
- **Проверено под systemd** (не только вручную): `systemctl --user start` → `status=0`,
  `delivered=True`. Живой дайджест пришёл в тему 138.

## 24-09-2026 — v2.1: от релея ссылок к русским выжимкам (фидбэк из поля)

- **Проблема:** первый формат (список ссылок) бесполезен — заголовки английские, сути в
  сообщении нет, а зарубежные ссылки у пользователя из РФ не открываются.
- **Решение:** бокс сам скачивает полный текст статьи (`trafilatura`) и главную картинку;
  **локальный Claude** (`claude -p`, без ключа, через подписку) пишет русскую выжимку:
  заголовок + 2–3 предложения сути + тейки + вывод. В тему «Новости» уходит **компактный
  русский дайджест** (заголовок + суть, ссылка сноской). Проверено вживую: качество RU
  высокое (напр. разбор статьи про RSA), доставлено в тему 138.
- **Стоимость под контролем:** обогащаем только топ-N свежих за прогон (`enrich_per_run`,
  сейчас 8), а не весь поток. N × вызов `claude -p` за прогон × 3/день — через подписку.
- **Тейки/вывод/картинка кэшируются** в таблице `enrichment` — для будущего «Подробнее».
- **Путь оценки по вкусу отложен:** `providers/`, `evaluator.py`, порог/`scores` в v2.1 не
  используются (таргетная фильтрация — на реакциях, этап 2). Файлы оставлены для будущего
  ранжирования, чтобы не переписывать.
- **v2.2 (след. заход):** интерактив «Подробнее» (свой бот-приёмник нажатий — у `notify`
  кнопок/callback нет) → полный разбор + картинка; туда же реакции 👍/👎 и обучение вкуса.

## 24-09-2026 — фильтр по вкусу и формат «заголовок-суть» (2-й фидбэк)

- **Фильтр релевантности включён сразу** (не «на реакциях потом»): Claude пачкой по
  заголовкам просеивает пул (`prefilter_pool`, 30) против профиля, обогащаем только топ-N
  прошедших (`enrich_per_run`). Нерелевантные помечаются пустой выжимкой — в кандидаты
  больше не возвращаются. Решение — СТРОГО по профилю (никаких захардкоженных категорий в
  промпте: перегиб «отсечь все гаджеты» ловится профилем, а не кодом).
- **Профиль под сисадмина:** железо/компьютеры/ноуты/планшеты/смартфоны, техпроцессы/чипы/
  архитектуры, техкомпании и рынок, инфра/DevOps/безопасность, ИИ, значимые финансы/геополитика.
  НЕ интересно: фотокамеры (Nikon), лайфстайл/спорт/развлечения, кликбейт. Профиль
  (`config/profile.md`) правится пользователем, отбор идёт по нему.
- **Формат выжимки переделан** под фидбэк: `headline` = сама суть новости одной ёмкой
  строкой (выделяется), `explain` = 1–2 предложения «что произошло и в чём интерес/прорыв».
  Тейки/вывод — для «Подробнее». Проверено вживую: Nikon отсечён, компьютеры/чипы/ИИ — нет.

## 24-09-2026 — v2.2: свой бот (Подробнее + реакции), заменил notify-доставку

- **Интерактив требует бота:** у `notify` нет инлайн-кнопок и приёма нажатий. Заведён свой
  бот `feed-agent-bot` (aiogram v3 + APScheduler), сервис `systemd/feed-agent-bot.service`.
  Токен — из Vaultwarden (`telegram/mycelium-charlie-news-bot`) через брокер `secret` в
  EnvironmentFile (`~/.config/feed-agent/env`, `FEED_BOT_TOKEN`); в коде/репозитории нет.
- **Бот сам планирует прогоны** (APScheduler, 9/14/20 UTC = 12/17/23 МСК) — прежний
  oneshot-таймер удалён. Пост-дайджест: один пост, нумерованный (заголовок-суть + 2 строки),
  под ним на КАЖДУЮ новость ряд кнопок [📖 Подробнее] [👍] [👎].
- **Кнопки:** [Подробнее] → разворот новости в ту же тему (тейки + вывод + картинка из
  статьи, всё уже кэшировано в `enrichment`); 👍/👎 → запись в таблицу `reactions` (сигнал
  для будущего обучения вкуса).
- **Доставка новостей теперь через бота**, а не `notify`. Шов `notify --to` оставлен как
  общий канал (полезен другим модулям). CLI `--once` — для отладки (сбор/сухой прогон).
- **Осталось для запуска:** пользователь создаёт бота в BotFather (сделано:
  `telegram/mycelium-charlie-news-bot`), добавляет его в группу ForBots, наполняет
  EnvironmentFile токеном (команда — в шапке сервиса) → включаем сервис.

## 24-09-2026 — v2.3: игры назад, «все новости», слияние дублей (3-й фидбэк)

- **Игры — обратно в интересы** (разбавление): чисто игровое больше не режется.
- **«Все новости, ничего не терять»:** пул фильтра большой (`prefilter_pool=200`, честно по
  источникам — по ~25 свежих с каждого, чтобы многочисленные RSS не вытесняли каналы);
  прежний «топ-8» убран. Прогон **почасовой** (minute=0). Доставка **постранично** — все
  готовые новости уходят сообщениями по `digest_max_items` (8) за прогон. Лимит
  `enrich_per_run=20` — лишь предохранитель от разовой лавины: остаток НЕ теряется, уходит
  следующим прогоном (об усечении — в лог, без «тихого» лимита). Ёмкость 20×24=480/день ≫ поток.
- **Слияние дублей:** Claude группирует посты об ОДНОМ событии из разных каналов
  (`group_duplicates`); тексты всех источников группы сливаются в один промпт → одна
  выжимка, взаимодополняющая источники; в дайджесте показываются все источники через " + "
  (поле `enrichment.sources`), прочие члены группы помечаются слитыми. Проверено вживую:
  новость про НДС 22% собралась из 6 постов (4 канала) в одну; «Цены на Lada» — 2 канала.
- **Стоимость/латентность:** прогон = 1 фильтр + 1 группировка + до 20 выжимок Claude
  (последовательно, ~10–20 мин). Ускорение — батч-суммаризация (несколько статей за вызов),
  отложено. `/news` форсирует прогон немедленно (ждать ~минуты), основной путь — авто-часовой.
